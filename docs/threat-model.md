# Denkbare Angriffe auf das Projekt

Das sind mögliche Szenarien, keine beobachteten Vorfälle oder Behauptungen über bestimmte Angreifergruppen.

| Szenario                                        | Eingebauter Schutz                                                                                                                              | Verbleibende Grenze                                                                                                    |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Erfundene Zitate / Satire falsch zuordnen       | Zentrale Bestätigung vor Katalog und Plugin-Veröffentlichung; Redaktion oder unabhängige autoritative Transkriptquelle plus kalibriertes Modell | Quellen, KI und Menschen können irren.                                                                                 |
| Prompt-Injection in Quellen                     | Untrusted Daten; Prüfer ohne Werkzeuge, begrenzte JSON-Ausgabe; lokale Analyse darf nicht selbst freigeben                                      | Skill-Instruktionen allein kontrollieren keinen kompromittierten Agenten.                                              |
| Ungeprüften/geänderten Text senden              | Frische Bindung an Video, Beleg und exakte bestätigte Frage; Ablauf, Rücknahme und Betriebsflags                                                | Kurzes Zeitfenster bis Browserklick; fremde Browser-Agenten können am Plugin vorbei handeln.                           |
| Login abfangen / Identität verwechseln          | Offizielle Tokenprüfung, Nonce, Browser-Cookie, Plugin-PKCE, kurzlebige einmalige Codes, verifizierte Pilot-Allowlist                           | Phishing und kompromittierte Endgeräte bleiben möglich. Google-Login autorisiert keine Social-Media-Veröffentlichung.  |
| Sitzung stehlen / neue Login-Quota erschleichen | Private lokale Dateien, gehashte Sitzung, Ablauf/Widerruf; stabiles Google-sub-Konto                                                            | Lokale Dateien sind kein Hardware-Tresor. Öffentliche Registrierung würde zusätzliche Sybil-Maßnahmen brauchen.        |
| Dienst/Redaktion fluten                         | Tages-/Anfragelimits, Größenlimit, begrenzte Jobs, kurze Flow-Lebenszeit, Wartung, Angriffsmodus                                                | Kein vollständiger DDoS-Schutz; Cloudflare-/Hosting-Grenzen zusätzlich betreiben.                                      |
| SSRF über Quellen                               | Nur explizit erlaubte öffentliche HTTPS-Ursprünge, keine Redirects/Anmeldedaten, Zeit-/Größenlimit                                              | Allowlist und DNS/Server dieser Quellen sind eine Vertrauensgrenze. Beliebige Nutzerdomains dort heben den Schutz auf. |
| Review-Action / Agentzugang kompromittieren     | Default-Branch, Opt-in, minimale Rechte, gepinnte Artefakte, konkrete private Agentrouten, Kalibrierungs-/Inhalts-Digests                       | Prüfer-Zugang bleibt privilegiert; gestohlene Secrets widerrufen und Codeänderungen kontrolliert ausrollen.            |
| Plugin-Update / Dependencies manipulieren       | Lockfile, gebündelte Runtime, Reproduzierbarkeitsprüfung, Publisher-/GitHub-Zugang schützen                                                     | Initiales Vertrauen in Publisher und Dependencies bleibt nötig.                                                        |
| HTML/Logs als Angriffskanal                     | textContent in Redaktion, keine Rohinhalte/Secrets in Action-Logs, kein nginx-Access-Log                                                        | Proxy-/Cloudflare-/Google-Protokolle vor Livebetrieb separat prüfen.                                                   |

Vor öffentlichem Betrieb priorisieren: echte Quellen-/Kalibrierungsabnahme, Google-Konfiguration und Rücknahme-/Angriffsmodus-Test. **Plugin-Versionen vor 0.2 besitzen die neue zentrale Kommentarsperre nicht und müssen aktualisiert werden.** Ein Server kann keine bereits heruntergeladenen oder fremden Agenten fernsteuern.

Regressionen prüfen Google-State/PKCE/Nonce/Replay, falsche Pilotkonten, stabile Quota, nur eigene Einreichungen, fehlende Quelle/Kalibrierung, Rücknahme/Ablauf/Flags, Opt-out, private Credentials und kein Doppelversand. Das beweist weder Fehlerfreiheit eines realen Modells noch echte öffentliche Sichtbarkeit eines Kommentars.
